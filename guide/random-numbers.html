무작위 번호는 어떻게 만들어질까

컴퓨터는 정해진 명령대로만 움직이는 기계입니다. 그런 컴퓨터가 어떻게 ‘예측할 수 없는’ 번호를 만들어 낼까요? 이 사이트의 번호 추출기가 공정한 번호를 뽑기 위해 사용하는 방법을 단계별로 설명합니다.

1. 의사 난수와 암호학적 난수

대부분의 프로그래밍 언어에는 난수 함수가 들어 있습니다. 자바스크립트의 Math.random()이 대표적입니다. 이런 함수는 의사 난수 생성기(PRNG)라고 부르는데, ‘시드(seed)’라는 시작값에 정해진 수식을 반복 적용해 그럴듯하게 무작위처럼 보이는 수열을 만듭니다. 시드와 수식을 알면 다음 값을 정확히 예측할 수 있기 때문에 ‘의사(擬似)’라는 이름이 붙었습니다.

게임이나 시각 효과에는 의사 난수로 충분합니다. 하지만 비밀번호, 암호 키처럼 예측되면 안 되는 값에는 암호학적으로 안전한 난수 생성기(CSPRNG)를 사용합니다. 운영체제가 하드웨어 타이밍, 인터럽트 같은 예측하기 어려운 물리적 잡음을 모아 시드로 쓰고, 출력값으로부터 내부 상태를 역산할 수 없도록 설계된 알고리즘을 사용합니다. 브라우저에서는 crypto.getRandomValues()로 이 난수원을 쓸 수 있습니다.

로또 번호를 뽑는 데 엄청난 보안이 필요한 것은 아니지만, “특정 번호가 더 잘 나오지 않는다”는 것을 자신 있게 말하려면 품질이 검증된 난수원을 쓰는 편이 낫습니다. 그래서 이 사이트는 CSPRNG를 사용합니다.

2. 숨어 있는 함정: 모듈로 편향

CSPRNG가 주는 것은 0부터 4,294,967,295(2³² − 1)까지의 32비트 정수입니다. 이것을 1~45 사이의 번호로 바꾸는 가장 쉬운 방법은 45로 나눈 나머지를 쓰는 것입니다.

번호 = (난수 % 45) + 1   // 간단하지만 아주 미세하게 불공정

문제는 2³²이 45로 나누어떨어지지 않는다는 점입니다. 2³² = 45 × 95,443,717 + 31이므로, 나머지가 0~30인 경우는 95,443,718번씩, 31~44인 경우는 95,443,717번씩 나옵니다. 즉 1~31번이 32~45번보다 아주 조금 더 자주 뽑힙니다. 이를 모듈로 편향이라고 합니다.

차이는 약 1억분의 1 수준이라 실제로 체감할 수는 없습니다. 하지만 고치는 방법이 간단하므로 굳이 남겨 둘 이유가 없습니다. 해결책은 버림 샘플링(rejection sampling)입니다. 45의 배수 중 2³²보다 작은 가장 큰 값(45 × 95,443,717)을 경계로 정하고, 난수가 그 이상이면 버리고 다시 뽑습니다. 그러면 남은 범위는 45로 정확히 나누어떨어져 모든 번호의 확률이 완전히 같아집니다. 다시 뽑아야 할 확률은 약 1억 4천만분의 1이라 속도에도 영향이 없습니다.

3. 중복 없이 6개 고르기

번호 하나를 공정하게 뽑을 수 있다면, 이제 서로 다른 6개를 골라야 합니다. 흔히 쓰는 방법은 두 가지입니다.

방법 A: 뽑고, 겹치면 다시 뽑기

1~45 중 하나를 뽑아 이미 나온 번호면 버리고 다시 뽑습니다. 결과는 공정하지만 이미 뽑은 번호가 많아질수록 헛수고가 늘어납니다.

방법 B: 통에서 꺼내기(비복원 추출)

1~45가 적힌 목록을 만들고, 목록에서 무작위 위치의 번호를 하나 꺼내 결과에 넣습니다. 꺼낸 번호는 목록에서 사라지므로 다음에는 44개 중에서, 그다음에는 43개 중에서 고르게 됩니다. 실제 추첨기에서 공이 빠져나가는 것과 같은 방식이며, 헛수고가 전혀 없습니다. 이 아이디어를 배열 안에서 자리 바꾸기로 효율적으로 구현한 것이 피셔-예이츠 셔플입니다. 이 사이트의 추출기는 방법 B를, 많은 횟수를 빠르게 돌려야 하는 시뮬레이터는 피셔-예이츠 셔플을 앞의 7칸까지만 수행하는 방식을 씁니다.

4. 이 사이트의 실제 코드

번호 추출기의 핵심 코드는 아래가 전부입니다. 누구나 브라우저의 ‘페이지 소스 보기’로 확인할 수 있습니다.

// 0 이상 max 미만의 정수를 균일하게 뽑기 (모듈로 편향 제거)
function randInt(max) {
  const limit = Math.floor(0x100000000 / max) * max;
  const buf = new Uint32Array(1);
  do { crypto.getRandomValues(buf); } while (buf[0] >= limit);
  return buf[0] % max;
}

// 1~45가 든 통에서 6개를 꺼내 오름차순으로 정렬
function pickSix() {
  const pool = Array.from({ length: 45 }, (_, i) => i + 1);
  const out = [];
  for (let i = 0; i < 6; i++) out.push(pool.splice(randInt(pool.length), 1)[0]);
  return out.sort((a, b) => a - b);
}

0x100000000은 2³²입니다. limit은 그보다 작은 max의 최대 배수이고, 난수가 이 값 이상이면 반복문이 다시 뽑습니다. 번호 고정·제외 기능을 쓰면 고정 번호를 먼저 넣고, 제외 번호를 뺀 통에서 나머지를 같은 방식으로 꺼냅니다.

5. 정말 공정한지 확인하는 방법

코드가 맞더라도 실제 결과로 확인해 보는 것이 좋습니다. 가장 간단한 방법은 번호를 아주 많이 뽑아 각 번호의 출현 횟수를 세는 것입니다. 예를 들어 6개씩 100만 게임을 뽑으면 번호 하나당 기대 출현 횟수는 600만 ÷ 45 ≈ 133,333번입니다. 공정한 생성기라면 각 번호의 횟수가 이 값에서 표준편차(약 340) 몇 배 이내로 흩어져 있어야 합니다.

통계학에서는 이를 카이제곱 적합도 검정으로 정량화합니다. 각 번호의 (관측값 − 기대값)² ÷ 기대값을 모두 더한 값이 자유도 44의 카이제곱 분포에서 흔히 나오는 범위(95% 구간 기준 약 28~64)에 있으면, 편향의 증거가 없다고 판단합니다. 공정한 생성기도 우연히 이 범위를 벗어날 수 있으므로, 여러 번 반복해서 대부분 범위 안에 드는지 보는 것이 정확합니다.

기억할 점: 공정한 추출기가 보장하는 것은 “모든 조합이 똑같은 확률로 나온다”는 것까지입니다. 아무리 좋은 난수를 써도 당첨 확률 자체는 1 / 8,145,060에서 바뀌지 않습니다.
